# Testing Summary — Payment & Reconciliation (`POST /orders/reconcile-payment`)

Here is a complete Markdown summary of everything tested and verified up to now against `inventory_db` (`inventory_postgres` container) and the Node.js application at `http://localhost:3000`.

---

## 1. Environment, Database & Auth Setup

| Check / Step | Action Taken | Result / Status |
| --- | --- | --- |
| **PostgreSQL Schema (`inventory_db`)** | Inspected `public` tables in `inventory_postgres` (`-U my_user -d inventory_db`) | Verified 10 tables exist: `categories`, `chat_history`, `items`, `order_items`, `order_status_history`, `orders`, `payment_attempts`, `payment_webhook_events`, `session`, `users` |
| **Docker Compose & Env Config** | Checked `.env` and `docker-compose.yml` (`postgres` service / `inventory_postgres` container) | Confirmed app connects via `docker-compose.yml` environment to `inventory_db` (`pgvector/pgvector:pg15`) |
| **Admin Authentication** | Sent `POST /login` as `admin` (`Admin@1234`) saving session cookie to `/tmp/cookies.txt` | Returned `HTTP/1.1 302 Found` with active authenticated session cookie |

---

## 2. Happy-Path Reconciliation Test (`200 OK`)

* **Setup:** Updated payment attempt `#3` (`order_id = 29`, `amount = 45.00`, `CARD`) to `SUCCEEDED` for testing.
* **Request:** `POST /orders/reconcile-payment` with `attemptId: 3`, `wrongOrderId: 29`, `rightOrderId: 25` (`total_amount = 45.00`, `UNPAID`, `PREPARING`).
* **Verified Outcome:**
* Returned `HTTP/1.1 200 OK`.
* **Attempt `#3**` was marked `FAILED` with `failure_code = 'reassigned_wrong_order'` and the cashier reason recorded in `failure_message`.
* **Attempt `#4**` was created on **Order `#25**` (`provider_payment_id = 'pi_test_057dc22892e3d4683d71_reconciled'`, `amount = 45.00`, `currency = 'INR'`, `status = 'SUCCEEDED'`).
* **Order `#29**` reverted to `payment_status = 'UNPAID'` with `payment_method`, `payment_reference`, and `paid_at` cleared (`null`).
* **Order `#25**` became `payment_status = 'PAID'` with `payment_method = 'CARD'`, `payment_reference = 'pi_test_057dc22892e3d4683d71'`, and `paid_at` populated.



---

## 3. Negative / Error-Handling Tests (`400 Bad Request`)

| Error Code | Test Input / Scenario | HTTP Status & Response | Notes / Cleanup |
| --- | --- | --- | --- |
| **`SAME_ORDER`** | `attemptId: 4`, `wrongOrderId: 29`, `rightOrderId: 29` | `400 Bad Request` — `{"code":"SAME_ORDER","error":"wrongOrderId and rightOrderId must be different."}` | Triggered immediately when source and target order IDs are identical |
| **`ATTEMPT_NOT_SUCCEEDED`** | Re-submitting already-`FAILED` `attemptId: 3` (`wrongOrderId: 29`, `rightOrderId: 25`) | `400 Bad Request` — `{"code":"ATTEMPT_NOT_SUCCEEDED","error":"Only SUCCEEDED attempts can be reconciled (current status: FAILED)."}` | Confirms already-reconciled/failed attempts cannot be re-reconciled |
| **`TARGET_ORDER_CANCELLED`** | Temporarily set attempt `#1` (`15.00`) to `SUCCEEDED` and targeted `CANCELLED` Order `#16` (`wrongOrderId: 28`, `rightOrderId: 16`) | `400 Bad Request` — `{"code":"TARGET_ORDER_CANCELLED","error":"Cannot apply payment to cancelled order #16."}` | Attempt `#1` and Order `#16` were restored afterward (`UPDATE 1` x 2) |
| **`AMOUNT_MISMATCH`** | Temporarily set attempt `#1` (`15.00`) to `SUCCEEDED` and targeted `UNPAID` Order `#4` (`72.00`) (`wrongOrderId: 28`, `rightOrderId: 4`) | `400 Bad Request` — `{"code":"AMOUNT_MISMATCH","error":"Attempt amount ($15.00) does not match target order #4 total ($72.00)."}` | Attempt `#1` was restored back to `FAILED` (`card_declined`) afterward |
| **`ATTEMPT_ORDER_MISMATCH`** | `attemptId: 4` (belongs to order `#25`) with distinct `wrongOrderId: 29` and `rightOrderId: 25` | `400 Bad Request` — `{"code":"ATTEMPT_ORDER_MISMATCH","error":"Attempt #4 belongs to order #25, not #29."}` | Verified with distinct `wrongOrderId` and `rightOrderId` values |

---

## 4. What Still Remains to Test

* **`TARGET_ALREADY_PAID`:** Testing against a target order that is already `PAID` (and not `CANCELLED`) with an amount matching the `SUCCEEDED` attempt.
* **Non-Admin Authorization (`403` / redirect):** Verifying a non-admin user session cannot call `POST /orders/reconcile-payment`.
* **UI / Browser Verification:** Confirming `http://localhost:3000/orders` renders Order `#25` as `PAID` and Order `#29` as `UNPAID`.
